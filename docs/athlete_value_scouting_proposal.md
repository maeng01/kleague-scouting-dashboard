# Athlete Value & Endorsement Fit Intelligence
## 선수 매니지먼트·엔도스먼트 의사결정 지원 도구 제안서

---

## 1. 프로젝트 배경

기존 스카우팅 애널리틱스 모델(원본 기획서)은 "누가 미래에 뛰어난 선수가 될 것인가"를 예측하는 ML 기반 잠재력 모델에 무게가 실려 있었다. 그러나 이 방향은 두 가지 현실적 문제를 갖는다.

1. **데이터 문제**: 유소년 시절의 historical dataset(성공/실패 선수 혼합 표본)은 공개적으로 확보하기 어렵고, 확보되지 않은 상태에서 무리하게 백테스팅을 구현하면 검증 불가능한 결과물이 된다.
2. **목적 불일치**: 지원하려는 직무(에이전시 선수 매니지먼트, 향후 스포츠 브랜드 엔도스먼트 담당)는 ML 예측 정확도가 아니라 **"이 선수를 어떻게 관리하고, 어떤 브랜드와 연결할 것인가"**라는 의사결정을 요구한다.

따라서 이 프로젝트는 방향을 재설정한다: **경기력 데이터는 선수를 이해하기 위한 기초 자료로만 쓰고, 프로젝트의 중심은 "선수-브랜드 적합도 판단"과 "에이전시 관점의 추천"에 둔다.**

---

## 2. 프로젝트가 답하려는 질문

> "이 선수를 계약/관리한다면, 어떤 전략으로 가치를 키우고 어떤 브랜드와 연결할 것인가?"

세부 질문:

- 이 선수의 현재 경기력과 성장 추세는 어느 정도인가? (기초 맥락)
- 이 선수의 팬덤·참여율·이미지는 어떤 수준이며, 어떤 카테고리(스포츠웨어/게임/테크/금융 등)와 궁합이 좋은가?
- 에이전시/브랜드 입장에서 이 선수에게 어떤 전략(장기계약, 개인 브랜딩, 스폰서 연결, 콘텐츠 강화)을 취해야 하는가?

---

## 3. 시스템 구조

```text
                 선수 기초 데이터 (경기력)
                          │
                          ▼
              ① Scouting Snapshot 모듈
        (포지션별 Per-90 · Percentile · 최근 성장 추세)
                          │
                          ▼
              ② Brand Fit & Marketability 모듈
   (참여율 · 팬덤 규모 · 이미지/가치관 적합성 · 카테고리별 적합도)
                          │
                          ▼
              ③ Agency Recommendation 모듈
     (강점/리스크 · 추천 전략 · 브랜드 매칭 제안 · 우선순위)
                          │
                          ▼
                Streamlit 대시보드 (선수 상세 페이지)
```

기존 기획서의 ML Potential Model·Historical Backtesting은 **"향후 확장 로드맵"**으로만 남기고 이번 구현 범위에서는 제외한다.

---

## 4. 모듈별 구현 방식

### ① Scouting Snapshot 모듈 (기초, 비중 작게)

- **데이터 소스**: FBref, Understat 등 공개 통계 (크로스섹션, 최신 시즌 기준)
- **범위 축소**: 포지션 1개(Winger 또는 Striker), 리그 1~2개, 표본 20~40명 선에서 시작
- **처리**: 결측치 처리 → Per-90 변환 → 동일 포지션·리그 내 Percentile 산출
- **산출물**: Radar Chart, Percentile Bar

이 모듈의 역할은 "예측"이 아니라 "이 선수가 지금 어떤 유형의 선수인지"를 빠르게 파악하는 맥락 제공용이다.

### ② Brand Fit & Marketability 모듈 (핵심, 비중 크게)

- **데이터 소스**: 공개 SNS 지표(팔로워 수, 최근 게시물 참여율 — 수동 수집 또는 공개 API 범위 내), 언론 노출 빈도(뉴스 검색 건수), 선수 스토리/이미지 요약(정성적으로 직접 태깅)
- **핵심 설계**: 팔로워 수 자체보다 **참여율(engagement rate)**과 **이미지·가치관 카테고리**를 우선 반영 (업계 트렌드에 맞춤)
- **Brand Fit 산출**: 선수별로 스포츠웨어/게임/테크/금융/여행 등 카테고리별 적합도를 정성 태깅 + 정량 지표를 결합한 반정량 점수로 산출 (예: 태깅 근거를 함께 표기해 판단 근거를 투명하게)
- **케이스 스터디 삽입**: Nike-오사카 나오미 사례처럼 "가치관 일치가 성공적인 파트너십으로 이어진" 실제 사례 1~2개를 프로젝트 내 비교 레퍼런스로 포함해 점수 체계의 설득력을 보강

### ③ Agency Recommendation 모듈

- Scouting Snapshot + Brand Fit 결과를 결합해 선수별 카드 형태로 출력:
  - 강점 / 리스크
  - 추천 전략 (장기계약 검토, 개인 브랜딩, 특정 카테고리 스폰서 연결, SNS 콘텐츠 강화 등)
  - 우선순위 (★ 표시)
- **제안서 자동 초안 생성 기능** 추가: 선수 카드에서 "스폰서 제안서 초안 만들기" 버튼 → 해당 선수의 강점·Brand Fit 근거를 활용한 1페이지 제안 요약을 자동 생성 (PPT/문서 스킬 연동 가능)

## 5. 기술 스택 (변경 없음, 범위만 축소)

| 영역 | 도구 |
|---|---|
| 데이터 처리 | Python, Pandas |
| 시각화 | Plotly (Radar/Percentile Chart) |
| 대시보드 | Streamlit |
| 데이터 저장 | CSV (MVP), 이후 SQLite |
| 제안서 생성 | python-docx 또는 PPT 템플릿 연동 |

바이브 코딩(Claude Code 등)으로 각 모듈을 독립적으로 완성 → 통합하는 순서로 진행하면 스코프 관리가 쉬워진다.

---

## 6. 개발 순서 (MVP 우선)

1. 포지션 1개, 리그 1~2개 선정 → 실제 데이터 확보 가능 여부 확인 (가장 먼저)
2. Scouting Snapshot 모듈 완성 (Per-90, Percentile, Radar Chart)
3. 선수 5~10명 대상 Brand Fit 데이터 수동 수집 (SNS·언론 노출·이미지 태깅)
4. Brand Fit & Marketability 모듈 완성
5. Agency Recommendation 카드 + 제안서 초안 생성 기능 완성
6. Streamlit 대시보드로 통합
7. (향후 확장, 이번 범위 제외) ML Potential Model, Historical Backtesting

---

## 7. 예상 결과물

- **웹 대시보드**: 포지션/리그/연령 필터 → 선수 리스트 → 클릭 시 상세 페이지(경기력 요약 + Brand Fit + Agency Recommendation + 제안서 다운로드 버튼)
- **케이스 스터디 페이지**: 실제 엔도스먼트 성공 사례 분석 1~2건을 대시보드 내 별도 섹션으로 포함
- **완성된 선수 5~10명 파일럿**: "제한된 표본으로 파일럿을 진행했고, 확장 계획은 이렇다"는 스토리를 명확히 제시 (표본 부풀리기보다 정직한 스코프가 신뢰도를 높임)

---

## 8. 기대 효과 / 활용 방향

- **브리온 지원용**: 선수 매니지먼트·스폰서십 유치 직무와 직결되는 "선수 관리 의사결정 도구"로 제시
- **향후 스포츠 브랜드 엔도스먼트 직무 지원용**: 동일 결과물을 "엔도스먼트 후보 스크리닝 및 브랜드 적합도 분석 도구"로 재프레이밍해 재사용 가능
- 기존 자산(oceans-app KBO CRM, HYROX 리포트, 에스포츠 스폰서십 리서치, 브랜드 캠페인 기획)과 함께 제시하면 "스포츠 산업 데이터·마케팅 실무 역량"이라는 일관된 궤적으로 보여줄 수 있음

---

## 9. 한계 및 정직하게 밝힐 부분

- 표본이 작아 통계적 일반화는 어려움 → "파일럿"임을 명시
- SNS/참여율 데이터는 공개 API 제약으로 일부 수작업 수집에 의존
- Brand Fit 점수는 정성적 판단이 섞인 반정량 지표이며, 완전한 예측 모델이 아니라 **의사결정 보조 도구**로 정의
- 이 프로젝트는 StatsBomb·Wyscout·Nielsen Sports·Hookit 같은 상용 스카우팅/엔도스먼트 분석 플랫폼을 대체하려는 목적이 아니다. 실제 실무에서는 이런 전문 데이터 기업의 제품이 쓰이는 경우가 대부분이며, 이 프로젝트의 목적은 **그 업계 표준 분석 로직을 직접 이해하고 구현해봄으로써 데이터 기반 사고방식을 증명하는 것**이다.
